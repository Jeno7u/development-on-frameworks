# Сервис учета рабочего оборудования

Консольное приложение из ПР3 дополнено базовым веб-интерфейсом на
Django 5.2. Сервис помогает учитывать рабочее оборудование, его состояние,
выдачу сотрудникам и возврат.

## Возможности

В веб-интерфейсе ПР5 доступны:

- главная страница с навигацией;
- список оборудования из `data/equipment.json`;
- карточка отдельного оборудования и его доступность;
- список выдач из `data/issuances.json`;
- карточка выдачи со связанными оборудованием и сотрудником;
- собственные страницы для неизвестных URL и идентификаторов.

Консольная версия ПР3 сохранена. В ней также работают добавление, поиск,
фильтрация, выдача и возврат оборудования с сохранением данных в JSON.

## Предметная область

Основные сущности проекта:

- `Equipment` - оборудование с названием, инвентарным номером, состоянием и
  признаком доступности;
- `Employee` - сотрудник с ФИО и электронной почтой;
- `Issuance` - выдача, связывающая оборудование с сотрудником и хранящая дату
  и признак возврата.

Активная выдача делает оборудование недоступным. После возврата история выдачи
сохраняется, а оборудование снова становится доступным.

## Технологии

- Python 3;
- Django 5.2;
- HTML и Bootstrap 5.3 через CDN;
- JSON как временное хранилище данных ПР3;
- pytest для автоматизированных тестов;
- flake8 для проверки качества кода.

## Страницы и view-функции

| URL | View-функция | Назначение |
| --- | --- | --- |
| `/` | `homepage.views.index()` | Главная страница |
| `/equipment/` | `equipment.views.equipment_list()` | Список оборудования |
| `/equipment/<int:equipment_id>/` | `equipment.views.equipment_detail()` | Карточка оборудования |
| `/issuances/` | `issuances.views.issuance_list()` | Список выдач |
| `/issuances/<int:issuance_id>/` | `issuances.views.issuance_detail()` | Карточка выдачи |

Маршруты распределены между корневым `equipment_service/urls.py` и файлами
`urls.py` приложений. `homepage.views.page()` создает единый HTML-каркас,
подключает Bootstrap и навигацию. `homepage.views.page_not_found()` является
общим обработчиком ошибки 404.

## Структура проекта

```text
development-on-frameworks/
├── manage.py
├── main.py
├── storage.py
├── utils.py
├── equipment_service/       # настройки и корневые маршруты Django
├── homepage/                # главная страница и общий HTML-каркас
├── equipment/               # страницы оборудования
├── issuances/               # страницы выдач
├── models/                  # классы и логика предметной области ПР3
├── data/                    # JSON-файлы
└── tests/                   # тесты ПР3 и веб-слоя
```

Пустые `models.py` в Django-приложениях оставлены для следующего этапа.
В ПР5 Django ORM, формы и шаблоны еще не используются: view-функции получают
объекты через существующий модуль `storage.py` и формируют HTML-ответы.

## Установка и запуск

Создайте и активируйте виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установите зависимости и примените встроенные миграции Django:

```bash
python -m pip install -r requirements.txt
python manage.py migrate
```

Запустите веб-приложение:

```bash
python manage.py runserver
```

Откройте <http://127.0.0.1:8000/>. Консольная версия запускается командой:

```bash
python main.py
```

## Проверка

```bash
python manage.py check
pytest -v
flake8 . --extend-exclude=.venv,venv
```

Для ручной проверки предусмотрены существующие идентификаторы
`/equipment/1/` и `/issuances/1/`, а также ответы 404 на
`/equipment/999/`, `/issuances/999/` и `/nonexistent/`.
