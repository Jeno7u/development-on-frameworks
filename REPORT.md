 Доработка индивидуального проекта

Существующий консольный проект ПР3 продолжен без удаления прежней логики.
Создан Django-проект `equipment_service` и три приложения:

- `homepage` - главная страница, общий HTML-каркас и обработчик 404;
- `equipment` - список и карточка оборудования;
- `issuances` - список и карточка выдачи.

Реализованы маршруты `/`, `/equipment/`, `/equipment/<id>/`, `/issuances/`
и `/issuances/<id>/`. Динамические страницы ищут объект по числовому
идентификатору и возвращают HTTP 404 при его отсутствии. Неизвестный адрес
обрабатывается общей оформленной страницей 404.

View-функции используют классы `Equipment`, `Employee`, `Issuance`, функции
поиска предметного слоя и загрузку из JSON, созданные в ПР3. Карточка выдачи
показывает связанные объекты оборудования и сотрудника. Страницы имеют общую
навигацию, адаптивный метатег `viewport` и оформление Bootstrap 5.3.

 Результат

В результате создан работоспособный начальный веб-интерфейс на Django,
настроена двухуровневая маршрутизация и реализованы view-функции. Данные
предметной области отображаются из JSON без дублирования бизнес-логики.
Консольная версия и тесты предыдущей работы сохранены. Проект подготовлен к
последующему переходу на шаблоны, Django ORM, формы и базу данных.

 Вывод

Практическая работа позволила связать URL, обработчики HTTP-запросов и
HTML-ответы в едином Django-проекте. Полученная структура отделяет веб-слой от
предметной логики и служит основой для дальнейшего развития приложения.
